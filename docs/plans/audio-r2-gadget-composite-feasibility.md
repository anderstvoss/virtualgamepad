# Audio round 2: `dummy_hcd` HID + UAC composite as Real USB

**Status:** decision brief, recommendation only. **No code, broker, IPC or realization-ID change.** All gadget/host/physical checks below are **not run**. This does not promote controller support, streaming quality or physical matching. Refs [#258](https://github.com/anderstvoss/virtualgamepad/issues/258), [#365](https://github.com/anderstvoss/virtualgamepad/issues/365) and [#408](https://github.com/anderstvoss/virtualgamepad/issues/408).

**Recommendation: reject `dummy_hcd` + `f_hid` + `f_uac1`/`f_uac2` as a Real USB audio replacement for the existing USB/IP implementation.** Linux v7.3 [`dummy_hcd` exposes no ISO endpoints](https://github.com/torvalds/linux/blob/c03c1a14507dfaf8b856c2608f9ac216021fc222/drivers/usb/gadget/udc/dummy_hcd.c#L135-L151) and [does not service ISO URBs](https://github.com/torvalds/linux/blob/c03c1a14507dfaf8b856c2608f9ac216021fc222/drivers/usb/gadget/udc/dummy_hcd.c#L1980-L1992); both [UAC1](https://github.com/torvalds/linux/blob/c03c1a14507dfaf8b856c2608f9ac216021fc222/drivers/usb/gadget/function/f_uac1.c#L215-L320) and [UAC2](https://github.com/torvalds/linux/blob/c03c1a14507dfaf8b856c2608f9ac216021fc222/drivers/usb/gadget/function/f_uac2.c#L388-L491) require isochronous streams. Merely combining gadget functions in configfs cannot create PCM transport. An ISO-capable UDC is a different proposal; descriptor matching and host acceptance would still be unverified.

The supporting [source-only research brief](https://github.com/anderstvoss/controller-protocol-research/blob/3994c15702290732547aef93e94f2d770fa4d16e/docs/usb-gadget-composite-real-usb.md) contains the ten pinned source records, ten claim records and planned checks. Its kernel evidence is not a physical gadget test.

## Baseline on current main

- **Native HID —** `linux.uhid.usb` + `audio-pipewire` represents the controller HID personality with independently created caller-session PipeWire audio endpoints. It has **no USB composite ancestry**; automatic HID/audio device association is not established. [Audio guide](https://github.com/anderstvoss/virtualgamepad/blob/62f98b628839d173e3b894111544eea6b62163a7/docs/CONTROLLER_AUDIO.md#L7-L27).
- **Real USB —** `linux.usbip.usb-audio` + `audio-usbip` provides a functional HID + UAC2 composite through VHCI and the existing installed root broker/dedicated worker. NativeClient ownership also needs `audio-pipewire`. It remains opt-in WIP, not a physical-audio matching claim. [Audio guide](https://github.com/anderstvoss/virtualgamepad/blob/62f98b628839d173e3b894111544eea6b62163a7/docs/CONTROLLER_AUDIO.md#L83-L111).
- **Existing dummy target —** `linux.dummy_hcd.usb-hid` is deliberately unavailable through ordinary constructors. It remains a HID-only experimental design, not an existing UAC realization. The f_hid GET_REPORT request metadata and per-report negative reply contract remains insufficient. [Support matrix](https://github.com/anderstvoss/virtualgamepad/blob/62f98b628839d173e3b894111544eea6b62163a7/docs/CONTROLLER_SUPPORT.md#L11-L38), [broker-only fixed prototype](https://github.com/anderstvoss/virtualgamepad/blob/62f98b628839d173e3b894111544eea6b62163a7/crates/gr-privileged-broker/src/dummy_hcd.rs#L1-L42).
- **Labels —** #408 proposes Generic / Native HID / Real USB as informative realization levels. Those are not a license to rename IDs or promote capability in this docs PR; the registry on the audited main still uses `PlayableReduced`, `PlayableFull` and `FaithfulUsb`. [Registry](https://github.com/anderstvoss/virtualgamepad/blob/62f98b628839d173e3b894111544eea6b62163a7/crates/gr-curated-controllers/src/registry.rs#L8-L30).
- **In-band audio —** Wii speaker and Steam PCM are controller-owned bounded HID subsystems, not separate UAC endpoints. ADR-0023 distinguishes them from out-of-band audio; ADR-0024 requires typed accepted-command accounting without altering broker IPC. [ADR-0023](https://github.com/anderstvoss/virtualgamepad/blob/62f98b628839d173e3b894111544eea6b62163a7/docs/adr/ADR-0023-controller-subsystems.md#L1-L42), [ADR-0024](https://github.com/anderstvoss/virtualgamepad/blob/62f98b628839d173e3b894111544eea6b62163a7/docs/adr/ADR-0024-host-output-stream.md#L1-L24).

Availability of a UAC gadget function does **not** extend those profiles to the other families.

## Which rejections would a newer kernel lift?

1. **Pre-v6.12 kernels:** a newer f_hid provides the positive `GADGET_HID_WRITE_GET_REPORT` mechanism for report IDs, eliminating the older unconditional empty reply *for supplied reports*. That feature exists on pinned v6.12 and v7.3; it is **not** sufficient to lift vg's refusal.
2. **v6.12 through pinned v7.3:** no exposed GET_REPORT report-type/host-length metadata, no explicit per-request negative reply, and a 64-byte report-response structure. The ordinary-root dummy_hcd refusal remains correct for all four declared Alpha 1 HID families. This docs PR does not expand allowed realizations.
3. **At pinned v7.3:** `dummy_hcd` still has no isochronous endpoints/URB support. No f_hid version change fixes UAC1/UAC2 audio. Proposed later kernel patches and out-of-tree UDC/Raw Gadget experiments are not release commitments.

## Proposed gate checks — **not run**

- **HID:** pin installed kernel/config, build an isolated f_hid-only gadget, exercise supported and unsupported GET_REPORT (type, ID, length), SET_REPORT modes, timeout, cleanup and multi-instance behavior. Capture semantic outcomes without private device data.
- **UAC under dummy_hcd:** separately try f_uac1 and f_uac2 plus f_hid in one configfs configuration; record actual binding error, descriptor enumeration (if any), USB host audio-card creation, ISO endpoint/URB status and teardown. Expected unsupported ISO is source-inferred, not a fabricated host observation.
- **Alternative ISO-capable UDC:** if separately approved, check descriptor/feature-unit fidelity, mixer controls, 4/2 and 2/1 sample paths, synthetic duplex PCM, reconnect, channel assignment and extended timing; verify permission boundaries independently.
- **Regression/acceptance:** leave existing USB/IP and UHID profiles, library API, worker/broker IPC, CI and claims untouched. A new implementation would require dedicated deterministic negative-ack and lifecycle tests, controlled host evidence, a separate owner decision and an approved privilege/IPC architecture.

**Decision:** Continue with USB/IP as the only compiled Real USB audio route; leave `dummy_hcd` as experimental HID-only/refused. Do not add a composite `dummy_hcd` realization or feature flag and do not promote a family, level or matching claim. Any future physical UDC route is a separate architectural proposal, not part of this Alpha 2 docs gate.
