## Goal, boundaries and vocabulary

Bring currently opt-in audio to **L1 reliable functional** bidirectional use, then **L2 native-host quality**, while retaining **L0 enumerated** and **L3 physical-matching** as distinct evidence tiers. Haptic byte/PCM fidelity does not imply physical actuator output. No new host audio provider, blanket ALSA device, MIDI endpoint, or PCM-shaped Wii UAC function is assumed.
- **Shape A:** `linux.uhid.usb` with explicit caller-session PipeWire sink/source sidecars, no USB ancestry; [ADR-0017 L13–16](https://github.com/anderstvoss/virtualgamepad/blob/4ac42325468b11a9edc3f6ba3295983ebaf04b43/docs/adr/ADR-0017-primary-realization-and-audio-components.md#L13-L16).
- **Shape B:** in-band, controller-owned bounded HID subsystems (Wii speaker and Steam PCM). Not UAC; [ADR-0023 L8–35](https://github.com/anderstvoss/virtualgamepad/blob/4ac42325468b11a9edc3f6ba3295983ebaf04b43/docs/adr/ADR-0023-controller-subsystems.md#L8-L35).
- **Shape C:** `linux.usbip.usb-audio` composite HID/UAC2 via VHCI, scoped privileged broker and unprivileged worker. ALSA-visible, with optional PipeWire NativeClient bridge; [audio guide L20–31](https://github.com/anderstvoss/virtualgamepad/blob/4ac42325468b11a9edc3f6ba3295983ebaf04b43/docs/CONTROLLER_AUDIO.md#L20-L31).
- Keep **representation** (Wii PCM/ADPCM, Steam S16LE PCM, MIDI commands, HD-rumble parameters), **transducer semantics** (speaker, microphone, grip L/R) and **presentation** (HID/UAC/ALSA/PipeWire) separate. Optional pure DSP utilities may be shared without making protocols interchangeable.
- Physical transducer impedance, size, resonance, safe drive and response are **unknown** unless separately measured. ALSA/PipeWire endpoint identity and channel labels are not measurements of hardware mechanics.

**A1 — PipeWire-only graph continuity (P0; after A0; parallel A2).** Test shape A without USB/IP, isolate callback/graph starvation versus upstream production versus downstream capture, preserve 1% production-rate envelope. **S1 — Wii speaker in-band implementation (P1/P2; requires S0 owner decision, the authorized #344 shared stream contract and D7 speaker gate).** Only `linux.uhid.bluetooth`; `linux.uinput` remains refused. Decode `0x40` signed 8-bit PCM and `0x00` Yamaha 4-bit ADPCM using `audio-wii-dolphin-pcm-adpcm-rate` and `audio-wii-dolphin-yamaha-adpcm-nibbles`; divisor formulas are **Dolphin source behavior**, not measured retail timing. **S2 — Steam typed PCM consumption (P1/P2; requires S0 owner decision and the authorized #344 shared stream contract).** Consume each host output `0x86` configure, `0x87` mono or `0x88` two-channel PCM with `0x44` feedback, using existing compiled decoder and **evidence `steam-d9-pcm-framing-feedback` / `steam-d9-pcm-stimulus-correspondence`**, not a new UAC/MIDI provider. **S3 — Optional application conversion prototype (P2; after S1 + S2).** **Wii 0x18 → decode → resample/limit → Steam 8 kHz S16LE stream** via explicit application-owned adapter, not automatically inside the core or provided as a generic Steam UAC interface.
