## Goal and decided context

Add `create_gamecube_adapter(CreationOptions, GameCubeAdapterOptions)` to the curated crate and ordinary root (C7), returning one adapter-level logical handle that can manage **four independently visible uinput evdev pads**, one per present port. There is no generic profile, silent realization fallback or four-device combined gamepad. Preserve four port slots, wired/WaveBird type and rumble-power indication in controller-native **topology/metadata** while keeping normal button/axis levels in `GameCubeAdapterInputs`. The adapter is a logical runtime owner even though the initial host sees separate pads.

- **First realization — `linux.uinput`:** playable, with port attach/detach represented by independent event-device create/remove. Buttons, two sticks, analog L/R and their independent digital clicks remain distinct; no threshold-generated click without an explicit documented policy. FF is exposed only when the selected port has a representable, actually handled path. This cannot masquerade as native USB adapter discovery.
- **Later faithful realization — USB-level gadget/device** (`dummy_hcd` or USB/IP class, pending implementation/host review): **one USB adapter** carrying four port reports and a per-port binary rumble command. SDL and Dolphin's *native adapter* backends use libusb and cannot open a mere `linux.uhid.usb` identity; UHID with adapter VID/PID is **not** a target. The USB provider is experimental (D5).
- **Out of scope:** the Switch 2 NSO GameCube controller (#360), USB-C / Switch 2 Pro protocols, PC-mode clones, generic third-party pads, retail firmware and real-device dumps.

C7 identity is **caller specified at creation, with unique per-instance defaults** (#156, #162). Publish which identity fields are actually representable on each target; uinput has separate per-port evdev identity and no native adapter serial/USB descriptor. Do not invent retail serial values, descriptors or firmware. The target post-VG-1b API is `GameCubeAdapterInputs`, `set_inputs`, per-field setters and `edit_inputs` delegating to **one transactional final-state validator**, plus `inputs()`. Battery, adapter identity, timing/clocks, host output and port occupancy/type/power are separate typed views. This brief **assumes VG-1b has finished**; do not build on the interim mixed-state API or introduce compatibility aliases. Preserve explicit `commit()`/`service()` semantics; a pre-commit press/release is not an edge queue.

The Linux kernel has no adapter-specific driver at the pinned research revision; separate out-of-tree Hinara and userspace ToadKing sources provide evdev mappings. Source evidence is the initial target; there is **no WUP-028 physical evidence**. Treat deterministic synthetic tests and live virtual-host tests as distinct provenance, never as retail measurement. ## Ordered steps (separate implementation PRs, each to `main`)

**17a. Registry, native inputs, topology and identity contract.** Register `virtualgamepad.gamecube-usb-adapter` and `gamecube-usb-adapter` with the compiled target table, per-port native controls and typed port topology/state. Define validated axis domains and explicit neutral behavior without guessing physical calibration. Introduce `GameCubeAdapterInputs` and the separated identity, clock, port presence/type and power views, using the completed VG-1b transactional core. Include creation options, per-instance identity isolation, typed refusals and exact target restrictions. **Done when:** tests cover all four distinct slot identities, neutral/bounds, disconnected-port refusal, rejected-edit atomicity, dirty flags, no-op updates, and topology mutations independent of snapshots.

**17b. Four uinput pads and reverse FF.** Create up to four **independent** evdev devices according to port presence, with explicit EV_KEY/EV_ABS range/flat/fuzz, independently held L/R analog and click, and optional per-port conventional FF. Follow source-supported mappings; do not claim native adapter rumble amplitude, hard-brake effect or WaveBird motor response. Track power/type in separate native metadata and refuse or suppress unrepresentable FF with typed diagnostics. **Done when:** deterministic fake-provider golden-capability tests and per-port hotplug/reorder/isolation, input, FF, power/type gates, failure rollback, repeated polling, removal and shutdown pass. Record any SDL mapping requirement as an external mapping, not a bundled one without evidence.

**17c. Converged constructors and consumer-facing wiring.** Expose `create_gamecube_adapter(CreationOptions, GameCubeAdapterOptions)` on curated and ordinary root, `inputs()`, `set_inputs`, family-specific setters and `edit_inputs` on the adapter handle, plus port-level typed metadata/topology operations. All setters delegate to the same final-state validator; no implicit target change or additional evdev pad beyond a present port. **Done when:** root/curated examples compile, target and identity selections are stable, failures leave no child nodes, and existing families retain parity. Update API snapshots, `docs/ALPHA_API_MIGRATION.md` and PR body with exact alpha API deltas (future implementation PRs only).

**17d. Faithful one-device USB realization — later, gated PR.** After reviewed descriptor/endpoints/polling evidence and a fresh #258 host-audit row/sign-off, implement a USB-level adapter (not UHID) with one identity, four port-state blocks, host SET_PROTOCOL/init, normal polling and per-port rumble reverse events. Test port transitions, different controller types, unknown bits, power gates, retries, all defined host requests/replies and interface-claim collisions. **Done when:** synthetic USB protocol tests pass and a permitted host demonstrates real USB-level enumeration with native SDL and Dolphin backends; otherwise mark WIP and do not promote native USB cells. No default system-wide privilege grants, kernel module loading or broker installation in this step without separately approved host policy.

**17e. Acceptance, timing and migration closeout.** Add the appropriate future `acceptance/` manifest and `docs/CONTROLLER_SUPPORT.md` matrix; run the #166 exact-owned-device creation/first-neutral consumer-readiness and node-gone removal measurements for N=1/4, repeated and concurrent port operations. Compare SDL evdev and RetroArch generic consumers for the first realization; compare native SDL HIDAPI and Dolphin **only for USB-level**. **Done when:** report records candidate SHA, exact kernel/consumer/build/hints, tested provider, commands/results, cold/warm distributions and resource baselines. The #166 first-valid-neutral oracle is still open, so preserve missing observations instead of claiming readiness or imposing a universal latency budget. Physical and never-run cells remain explicitly untested.

## Host setup and audit impact

#258's signed-off release defaults remain: existing host grants for creator `/dev/uinput` or `/dev/uhid`; existing distro/seat policy for `/dev/input/event*` and hidraw; no automatic broad device grant. `linux.uinput` needs creator access to `/dev/uinput`, plus consumer event-node ACL and optional FF write permission; this is within the existing audit class, but measure its use for four pads.

**New surfaces for 17d (dev changes, not implicitly authorized):** `dummy_hcd` module availability/loading and any kernel config/configfs gadget setup; USB/IP worker and virtual USB attach/broker/service scope where selected; `/dev/bus/usb/*` node ACL or per-device udev `uaccess` policy for libusb open and OUT/IN; possible kernel-driver detach/rebind and exclusive interface claims; module unload, crash cleanup, sandbox/Flatpak access and concurrent-consumer collision. For each, amend `docs/ALPHA_2_HOST_AUDIT.md` with mechanism, who, privilege, scope/persistence, security/other-device impact, reversible cleanup, safe release default and evidence, then obtain **new Anders sign-off** before enabling the USB provider. Prefer per-device, seat-scoped opt-in; never globally relax permissions. No real Bluetooth dependency.

## Snapshot, migration and acceptance consumers

This docs PR changes **no code, API snapshots, `acceptance/` files, host policy or protocol pins**. Each later implementation step updates its own affected snapshots, migration guide, registry/evidence pin and acceptance rows.
