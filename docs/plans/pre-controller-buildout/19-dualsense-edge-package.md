## Goal and decided context

Recommend a **separate curated controller package** with its own `virtualgamepad.dualsense-edge` compiled ID, handle, controller-native `DualSenseEdgeControl`, `DualSenseEdgeInputs`, `DualSenseEdgeOptions` and identity. The common Sony family is a research relationship and an internal code-reuse opportunity, not a reason to change the ordinary DualSense's 13-control enum or silently select Edge by PID. Distinct product (Sony VID 0x054c, Edge PID 0x0df2 versus DualSense 0x0ce6), Edge-specific consumer capabilities, unverified descriptors and distinct profile/feature requirements justify separate typed public contracts. No generic mutable controller state, runtime descriptor injection, implicit fallback, or generic extra-button bag. The exact separate package versus controller-owned variant decision is for Anders below.

- **First: `linux.uhid.bluetooth`** — local Bluetooth-bus HID presentation; native HID-aware consumers, with input and evidenced reverse paths. It is not radio, discovery, or pairing (#164). Target source evidence first, retail fidelity only when corroborated.
- **Second: `linux.uhid.usb`** — independent USB-bus HID presentation, different report framing and probe; does not expose a real USB device or audio interfaces. Both UHID targets can be playable before full protocol fidelity.
- **Reduced playable: `linux.uinput`** — driver-shaped evdev, including the four source-backed auxiliary event codes where supported, subject to exact target capability and consumer checks. Not the native HID protocol; do not fabricate a hardware/firmware identity, raw feature response, SDL mapping or BTN_GRIP code. No silent alias to face buttons.
- **Later USB-level fidelity:** USB/IP production target; `dummy_hcd` secondary as needed, experimental and presently constrained by f_hid request metadata/negative-reply limitations. This follows brief 17 and the #296 owner decision (comment 6807419275). Each path independently requires owner-reviewed evidence and host audit. Do not reuse the standard Sony composite USB audio profile under Edge identity. Audio and advanced trigger parity remain unproven; respect #116/#143/#145, #161 and #136.
- Compat shims only with explicit creation toggles, documented defaults and evidence; no provider-owned Sony semantics or faux profile success. Real Bluetooth deferred.

C7: expose `create_dualsense_edge(CreationOptions, DualSenseEdgeOptions)` in curated and ordinary root. Caller-specified validated identity at creation, unique per-instance defaults, stable within promised recreation semantics (#156, #162); keep model selection fixed by the package. Specify identity fields and target limitations rather than claiming arbitrary retail metadata restoration; coordinate #161 for Sony model/metadata queries. Validate explicit duplicate/concurrent identity behavior and reject unsupported identity options before opening a provider. No physical identity cloning, published identifiers or captured private payloads.

Post-VG-1b target API: `DualSenseEdgeInputs` contains caller input levels only: base native buttons, D-pad, sticks, triggers, touch and motion where proven, plus Fn1, Fn2, left paddle and right paddle as four independent native controls under the source-supported common report layout. Battery/charging, identity, protocol clocks/counters and topology are separate typed read/update views; retained host outputs are separate; profile/remap state is not an input field. Native types are not widened to cover target limitations. `inputs()`, `set_inputs`, per-field setters, `edit_inputs` and neutralize share one realization-aware transactional final-state validator. Rejected edits leave accepted levels, dirty state and clocks intact; identical edits add no work and preserve pending frames. Preserve explicit commit/service and immutable retry bytes; caller commits between important edges. No consumer-visible atomicity promise or edge queue. VG-1b steps d and e are still landing; **assume all are complete**, no interim API or compatibility aliases.

### Shared versus new implementation

Inspect [standard curated DualSense](https://github.com/anderstvoss/virtualgamepad/blob/12358d71d762fb438cbf01f5b120986279a8540d/crates/gr-curated-controllers/src/dualsense.rs), [USB protocol](https://github.com/anderstvoss/virtualgamepad/blob/12358d71d762fb438cbf01f5b120986279a8540d/crates/gr-curated-controllers/src/dualsense/protocol.rs), [host probe](https://github.com/anderstvoss/virtualgamepad/blob/12358d71d762fb438cbf01f5b120986279a8540d/crates/gr-curated-controllers/src/dualsense/host_probe.rs), [worker state](https://github.com/anderstvoss/virtualgamepad/blob/12358d71d762fb438cbf01f5b120986279a8540d/crates/gr-curated-controllers/src/dualsense/worker_state.rs), [Sony evdev](https://github.com/anderstvoss/virtualgamepad/blob/12358d71d762fb438cbf01f5b120986279a8540d/crates/gr-curated-controllers/src/sony_evdev.rs) and [wire module](https://github.com/anderstvoss/virtualgamepad/blob/12358d71d762fb438cbf01f5b120986279a8540d/crates/gr-controller-wire/src/dualsense.rs). Standard DualSense is already input-only after its VG-1b/d step; its USB protocol, numbered reports, synthetic feature replies, retained output, USB worker bridge and target restrictions are precedents. Its compiled targets are uinput, USB-bus UHID, dummy_hcd and USB/IP audio; **there is no Bluetooth-bus DualSense implementation to simply enable**. Edge needs a new transport-aware HID session/codec (including Bluetooth-specific CRC, numbering, scheduling and requests), per-model descriptor/identity/features, auxiliary-control encoder, target restrictions, and separately qualified output decode. Reuse common session, validation and identity-generation primitives, evidence-matching shared Sony field encoding, bounded retained output and compound evdev association helpers if applicable. Extract narrowly and prove existing DualSense bytes and public behavior unchanged. Do not copy its firmware or capability reply values, calibration data, USB cadence, descriptor, audio profile or worker state wholesale; their Edge applicability must be established independently. Gate T's test-only state proved representation, not a production driver.
