## Goal and decided context

Add independent `create_switch2_joycon_left(CreationOptions, Switch2JoyConLeftOptions)` and `create_switch2_joycon_right(CreationOptions, Switch2JoyConRightOptions)` (proposed names) in curated and ordinary root (C7). Each half is one controller with one primary realization selected at creation; a pair is two separate handles and two devices. Do not emit a third, combined controller, including the SDL pair mapping identity. Orientation/pairing is the application's or consumer's responsibility; receiver topology belongs to #165. The Switch 1 family (#297) is the closest structural model, not a compatible wire protocol.

- **First: playable `linux.uinput`.** One evdev gamepad per half, with native side-specific controls, one stick, right C and both grip-side controls. An ordinary evdev mapping need not match SDL's sideways mapping; let the consumer map it. Do not advertise native libusb recognition, motion or mouse on this path.
- **Later: faithful USB-level target.** USB/IP is the production target, following brief 17 / #296 owner comment 6807419275. The current USB/IP audio realization is not this transport. A composite HID plus vendor-class USB bulk command/reply personality is required. A separately authorized, experimental `dummy_hcd` path is secondary and only useful if extended beyond its current HID-only limitations. Each provider requires its own #258-style audit amendment and renewed owner sign-off.
- **Not targets today:** USB-bus UHID cannot present vendor bulk topology; Bluetooth-bus UHID has no demonstrated native recognition path at the reviewed pins. Neither is a native USB substitute. Actual Bluetooth discovery/pairing/reconnect remains #164. No rail, charging-grip, combined-receiver or Switch 1 compatibility transport is inferred. No firmware analysis or device dumps.

Assume **VG-1b d/e have landed** (not true of the reviewed interim baseline). Use distinct `Switch2JoyConLeftInputs` and `Switch2JoyConRightInputs` with per-side native buttons, one stick in a documented native domain and, when supported by reviewed evidence, native gyro/accelerometer data. The input shapes are not generic evdev layouts. `inputs()` reads the accepted inputs; `set_inputs`, per-field setters, `edit_inputs` and neutralize delegate to the same transactional final-state validator and transition core. Reject unsupported non-neutral fields identically from all routes; reject invalid values atomically, preserve dirty and pending work on rejection or no-op, derive controller-owned clocks only from defined accepted transitions. No implicit fallback, generic masks or queue of intermediate button edges. Preserve explicit commit/service and caller commit between important edges. Keep identity, battery/charging, clocks, topology, calibration resources, report modes and retained host outputs separate typed views; do not invent unproven fields or formats. Motion samples and mouse displacement have distinct semantics; mouse is not stick, IMU or touch.

Caller-specified identity at creation with per-instance defaults (#156, #162 policy context). Keep the per-half product type distinct from instance identity; independently generated defaults must not collide and must remain stable for the promised lifecycle. Expose only evidenced and representable identity fields per target; refuse unsupported override fields before provider open. Uinput's event identity is not a native USB descriptor or serial. Never publish identifying device values or pairing material.

Amend `docs/ALPHA_2_HOST_AUDIT.md` or the owner-designated successor with mechanism, who/privilege, scope/persistence, security and effects on other devices, reversible cleanup, safe release default and evidence for each new path.
