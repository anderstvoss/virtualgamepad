## Goal and decided context

A single controller-native logical handle, provisionally `create_switch2_gamecube(CreationOptions, Switch2GameCubeOptions)` in curated and ordinary root (C7). Not the four-port WUP-028 adapter (#296), not a Switch 2 Pro alias, and not a runtime configuration profile. Preserve the GameCube-specific control surface, including the C control, distinct digital click/shoulder inputs and independent analog L/R travel. No automatic conversion from trigger travel to click, invented Pro paddles, HD rumble or generic state widening.

- **Playable first — `linux.uinput`:** one evdev pad with the evidenced Linux GC control shape, explicit range and capability deviations, conventional FF only where a tested translation to native simple rumble is representable. Generic evdev/SDL joystick acceptance is a target, not established. This is not a native SDL Switch 2 USB device.
- **Faithful candidate — new USB/IP vendor-bulk realization:** one compiled USB device identity (consumer match Nintendo 057e:2073), vendor-class bulk IN/OUT, staged opening and native input/output. USB/IP is the production target by the brief 17 owner precedent (#296 comment 6807419275); its current audio personality is not this protocol. Transport work itself starts WIP. `dummy_hcd` is secondary when useful, experimental, and needs an appropriate vendor-bulk gadget function rather than existing HID-only `f_hid`. Do not enable either through another realization or silent fallback.
- `linux.uhid.usb` cannot supply the required USB interfaces and bulk endpoints, even with matching VID/PID. It is not a faithful or proposed playable target. Bluetooth-bus UHID is locally available infrastructure, but no reviewed GC Bluetooth report map, descriptor or consumer binding establishes a target here. Keep it Not supported pending separate research; real Bluetooth, pairing and discovery remain deferred (#164). Do not infer that the retail device lacks Bluetooth.

**Target post-VG-1b API:** family-typed `Switch2GameCubeInputs`, `set_inputs`, family-native per-field setters and `edit_inputs` over one transactional final-state validator, plus `inputs()`. Assume VG-1b d/e have landed; do not build against the interim state type or introduce aliases. Battery/status, caller-created identity, protocol clocks, topology, calibration/resources and retained host outputs are separate typed views where evidence warrants them; no fabricated topology or telemetry fields. Native outputs are simple single-motor rumble, with indicators only if evidenced. Neutralize only caller inputs. Invalid/non-representable non-neutral states are rejected before installation, leaving dirty and pending work unchanged; equal accepted edits add no new dirty work. Preserve explicit `commit()` and `service()`; callers commit between meaningful edges. No generic event queue, multi-writer mask or provider-owned family protocol.

Caller-specified identity at creation with per-instance defaults (#156, #162): stable within the documented lifecycle, isolated across concurrent instances. Source-backed USB VID/PID/type and the evdev projection are not interchangeable. Expose only evidenced, representable metadata; distinguish identity from release/version, protocol mode and calibration. A consumer's identity read is not a measured retail identifier. Compatibility behavior, if needed and evidenced, is named, opt-in/toggleable at creation and has both on/off tests; it must not redefine native state or silently falsify fidelity.

## Host setup and audit impact

The signed-off #258 baseline is not blanket authorization for new host surfaces. Existing `linux.uinput` needs ordinary creator permission to /dev/uinput and separate consumer ACL for event nodes (and effect writes if FF). Record exact association, distro/seat policy and read-only preflight; no broad input-group membership or default root daemon. Distinguish missing permissions from protocol defects.

**New dev changes, each requiring separate amendment to `docs/ALPHA_2_HOST_AUDIT.md` and new Anders sign-off before enabling:** USB/IP worker/VHCI attach privileges, module registration, USB device/endpoint node permissions and authorized service/broker scope; secondary dummy_hcd kernel config/module, gadget/configfs and vendor-bulk function creation/cleanup. For each, inventory who, privilege, scope/persistence, impact on unrelated devices, opt-in release default and reversible teardown, crash cleanup, concurrent interfaces and sandbox access. Native libusb requires specific /dev/bus/usb node access; hidraw permission alone is insufficient. Kernel binding and libusb claims/detach/rebind may be mutually exclusive; run separately and restore ownership. Prefer per-device seat-scoped opt-in. Any privileged surface needs its own realization ID; no global rules, automatic module loads, persistent service enrollment or IPC changes without approval. Steam permission rules alone do not prove client support. No real Bluetooth host setup in this brief.
