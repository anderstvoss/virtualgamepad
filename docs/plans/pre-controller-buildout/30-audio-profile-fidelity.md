# Brief 30: USB audio profile fidelity by controller family

**Status:** Proposal only; source review, not a device capture or host acceptance. **Release:** Alpha 2 gate [#365](https://github.com/anderstvoss/virtualgamepad/issues/365). **Owner constraints:** Keep existing realization IDs and add the Generic / Native HID / Real USB level labels per [#408](https://github.com/anderstvoss/virtualgamepad/issues/408); no broker upgrade, worker/broker IPC change or changes to PR #402.

## Baseline on current main

[Compiled audio profiles](https://github.com/anderstvoss/virtualgamepad/blob/62f98b628839d173e3b894111544eea6b62163a7/crates/gr-curated-controllers/src/audio.rs) are interleaved **S16LE, 48 kHz** with synchronized channels. The [USB/IP composite builder](https://github.com/anderstvoss/virtualgamepad/blob/62f98b628839d173e3b894111544eea6b62163a7/crates/gr-usbip/src/profile.rs) creates **UAC2** (fixed clock and terminals, without UAC feature-unit descriptors) plus HID. Its packet-capacity formula is `49 × channel_count × 2` bytes, with high-speed endpoint interval 4; matching packet capacities alone is not descriptor or clock equivalence.

| Family | VG playback / capture | Evidence for physical USB sound | Physical unknowns |
| --- | --- | --- | --- |
| **DualSense** | **4 / 2**; headphone L/R then grip L/R; capture pair; onboard-speaker intent reuses audible R | Maintainer-documented **UAC1 1.00**, S16LE **48 kHz** playback/capture; output channel mask `0x0033` (FL/FR/RL/RR), input `0x0003` (FL/FR); mute/volume **feature units 2 and 5**; playback endpoint `0x01` adaptive **392 B max**, capture endpoint `0x82` asynchronous **196 B max**, both interval 4. See [existing source claim](https://github.com/anderstvoss/controller-protocol-research/blob/ec629212a9c34217659b646bb07d05ddeb3740bc/records/claim/audio-dualsense-usb-uac1-topology.json). | Numeric physical **input/output terminal type codes**, other supported sample rates, complete feature-unit control behavior, microphone routing and measured profile parity: [gap claim](https://github.com/anderstvoss/controller-protocol-research/blob/ec629212a9c34217659b646bb07d05ddeb3740bc/records/claim/audio-dualsense-usb-terminal-rate-gaps.json). |
| **DualShock 4** | **2 / 1**; functional stereo + mono capture | No physical UAC version, sampling rate, channel roles, feature units, terminal types or packet bounds established by the reviewed Linux sound tables and SDL/HID sources: [DS4 gap](https://github.com/anderstvoss/controller-protocol-research/blob/ec629212a9c34217659b646bb07d05ddeb3740bc/records/claim/audio-dualshock4-usb-physical-descriptor-gap.json). | **All physical UAC fields listed** remain unknown, including whether the USB sound presentation is class-compliant. This does **not** establish absence of audio hardware. |
| **Xbox 360 (standard HID)** | **2 / 1**; functional stereo + mono capture | The reviewed Linux `xpad` path does **not** expose headset PCM as an ALSA UAC card, and these USB-audio maps do not supply an Xbox 360 audio profile: [xpad claim](https://github.com/anderstvoss/controller-protocol-research/blob/ec629212a9c34217659b646bb07d05ddeb3740bc/records/claim/audio-xbox360-xpad-no-headset-audio.json), [existing wired-USB descriptor gap](https://github.com/anderstvoss/controller-protocol-research/blob/ec629212a9c34217659b646bb07d05ddeb3740bc/records/claim/x360-l0-device-physical-wired-usb-unknown.json). | Physical USB/XInput headset framing, UAC applicability, rates, channels, mute/volume, terminals and endpoint packets. **Do not** infer that proprietary headset audio is absent. |

The DualSense audio figures above are an **existing maintainer record**, not measurements by this lane. The [ALSA UCM HiFi profile](https://github.com/anderstvoss/controller-protocol-research/blob/ec629212a9c34217659b646bb07d05ddeb3740bc/records/claim/audio-dualsense-alsa-ucm-roles.json) defines four output/two input channels and maps headset playback to channels 0/1, speaker to channel 1, built-in mic to capture 0 and headset mic to 0/1; it does **not** establish grip/haptic roles by itself. Prior physical listening is separately recorded in the VG [audio experiment](https://github.com/anderstvoss/virtualgamepad/blob/62f98b628839d173e3b894111544eea6b62163a7/docs/history/alpha-1/experiments/EXP-0023-controller-audio.md).

The pinned [Linux `sound/usb/mixer_quirks.c`](https://github.com/anderstvoss/controller-protocol-research/blob/ec629212a9c34217659b646bb07d05ddeb3740bc/records/source/audio-linux-usb-dualsense-mixer-quirks.json) says DualSense is UAC1, creates headphone/mic jack controls using **terminal IDs 3/4**, and correlates HID jack events to the **same USB-device ancestry** as the sound card. These IDs are **not** `wTerminalType` values. Neither the reviewed [USB audio quirks table](https://github.com/anderstvoss/controller-protocol-research/blob/ec629212a9c34217659b646bb07d05ddeb3740bc/records/source/audio-linux-usb-quirks-table.json) nor [mixer-map table](https://github.com/anderstvoss/controller-protocol-research/blob/ec629212a9c34217659b646bb07d05ddeb3740bc/records/source/audio-linux-usb-mixer-maps.json) provides a DS4/Xbox 360 physical audio descriptor. A missing special-case table entry is not evidence that a generic class-compliant interface cannot enumerate.

## Consumer consequences by existing realization level

| Level and ID (unchanged) | Current audio presentation | Fidelity / association consequence |
| --- | --- | --- |
| **Generic** — `linux.uinput` | Generic evdev controller; no USB Audio Class topology | Do not label the 2/1 or 4/2 PCM profiles as native audio capability at this level. |
| **Native HID** — `linux.uhid.usb` + `audio-pipewire` | Controller-specific USB-bus HID plus separate PipeWire sink/source in caller session | Explicit app/node selection is required. A sidecar does **not** gain the USB ancestry or ALSA `CardComponents` needed for native DualSense UCM matching and kernel jack association; see [association gap](https://github.com/anderstvoss/controller-protocol-research/blob/ec629212a9c34217659b646bb07d05ddeb3740bc/records/claim/audio-consumer-sidecar-hid-sound-association-unknown.json) and [UCM matcher](https://github.com/anderstvoss/controller-protocol-research/blob/ec629212a9c34217659b646bb07d05ddeb3740bc/records/claim/audio-consumer-dualsense-ucm-usb-ids.json). Channel roles can still be useful to an explicitly routed client. |
| **Real USB** — `linux.usbip.usb-audio` + `audio-usbip` | Composite USB device through the existing root broker, HID + UAC2, optionally bridged to PipeWire native clients | Actual USB sound-card enumeration is possible, but **DualSense's class version is wrong**, feature-unit topology is incomplete and physical terminal types remain unverified. DS4 and Xbox 360 are functional, not native, identities. All three use VG's fixed 48 kHz settings; only the documented DualSense 48 kHz configuration has physical reference evidence. |

UCM selection is not a substitute for descriptor parity: selecting `Sony/DualSense-PS5` from the USB ID still leaves physical channel routing, control IDs, clock behavior and jack ancestry to qualify. The 4-channel DualSense playback role order is consumer-visible, whereas DS4 and Xbox 360 channel semantics are assumed by VG, not physically established.

## Proposed implementation sequence (none implemented here)

1. **DualSense — Real USB required for native UAC fidelity.** Capture and independently review the missing physical terminal types, full alternate/rate set and feature controls; then propose a **UAC1** family-specific USB composite with feature units, compatible jack ancestry and stable channel order. Compare ALSA card/UCM selection, volume/mute, routing and endpoint descriptors on the *same host* before claiming parity. The Native HID sidecar may remain a labeled functional option, not UCM-matching audio. No broker protocol changes are proposed.
2. **DS4 — evidence first, Real USB only if justified.** Obtain privacy-reviewed physical USB configuration/audio descriptors and ALSA mixer/UCM behavior; determine UAC presence/version, physical stream rates/channels, terminals, controls and packets before modifying descriptors. Retain the 2/1 Native HID sidecar solely as functional audio and preserve explicit unknown status.
3. **Xbox 360 — separate proprietary headset from UAC.** Inspect public wired headset/XInput consumer paths before designing any native headset realization. Do **not** substitute a generic UAC2 sound card and call it Xbox 360 USB fidelity. Keep an opt-in functional sidecar where supported; native/Real USB headset parity remains unproposed until its transport and host-binding contract are established.
4. **Regression and qualification gate — all not run.** Deterministic descriptor/control tests should assert UAC revision, `wTerminalType`, feature-unit IDs, channel layouts, alternate sample rates, and endpoint `wMaxPacketSize`/`bInterval`. Future owner-run Linux checks should compare physical/virtual ALSA enumeration, UCM selection, headset vs onboard-speaker and grip routing, microphone response, mute/volume, same-USB ancestry, reconnect and teardown. Record results separately for Native HID and Real USB. No host, physical, timing or microphone test was run for this brief.
