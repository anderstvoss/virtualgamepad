# Brief 31: Wii Remote speaker as a host audio source (design only)

Read [ground-rules.md](ground-rules.md) first. **Status:** proposal; no implementation, API approval, host test or acceptance promotion. **Refs:** #158, #365; audio round 2, ar5. **Recommendation:** Option A first; defer Option B to a separate explicitly approved feature.

## Current contract and evidence boundary

At vg [`62f98b6`](https://github.com/anderstvoss/virtualgamepad/commit/62f98b628839d173e3b894111544eea6b62163a7), [`WiiSpeakerDecoder`](https://github.com/anderstvoss/virtualgamepad/blob/62f98b628839d173e3b894111544eea6b62163a7/crates/gr-curated-controllers/src/wii_remote/codec/speaker_decode.rs#L1-L191) produces **candidate** `WiiSpeakerOutput` records and 16-bit decoded mono samples; it does **not** publish accepted records to the application, create an audio endpoint or play anything. Its `WiiSpeakerData` contains the original 21-byte report, encoded length, enable/mute state, register configuration, disposition and bounded samples. Only a controller's semantic commit can advance the decoder and publish an **accepted** command. The present Wii controller [offers `linux.uinput` and `linux.uhid.bluetooth`](https://github.com/anderstvoss/virtualgamepad/blob/62f98b628839d173e3b894111544eea6b62163a7/crates/gr-curated-controllers/src/wii_remote/controller.rs#L15-L87); the latter is a *Bluetooth-bus UHID presentation*, **not** pairing or radio transport. Wii speaker S1 journal wiring has not landed on this base.

[ADR-0024](https://github.com/anderstvoss/virtualgamepad/blob/62f98b628839d173e3b894111544eea6b62163a7/docs/adr/ADR-0024-host-output-stream.md#L35-L116) supplies a bounded, controller-owned, cursor-replayed host-output journal with `(epoch, sequence)`, exact gap reporting and terminal state, separate from retained latest values and lossy `service()` observations. Its generic core is not equivalent to Wii family wiring. [ADR-0023](https://github.com/anderstvoss/virtualgamepad/blob/62f98b628839d173e3b894111544eea6b62163a7/docs/adr/ADR-0023-controller-subsystems.md#L8-L53) treats speaker traffic as a controller-native **in-band HID subsystem** and rejects impersonating UAC. [ADR-0017](https://github.com/anderstvoss/virtualgamepad/blob/62f98b628839d173e3b894111544eea6b62163a7/docs/adr/ADR-0017-primary-realization-and-audio-components.md#L8-L24) permits explicitly associated caller-session PipeWire components without claiming USB ancestry. [Brief 16](16-audio-haptics-buildout.md) and [speaker decode notes](../../WII_SPEAKER_DECODE.md) remain the S1 evidence/qualification boundary; neither reports audible Wii speaker support.

Issue [#408](https://github.com/anderstvoss/virtualgamepad/issues/408) proposed renaming realization IDs, but the subsequent owner disposition recorded in [#365](https://github.com/anderstvoss/virtualgamepad/issues/365) **keeps IDs** and adds informative levels **Generic / Native HID / Real USB**. Here Native HID for Wii means existing `linux.uhid.bluetooth`, **not** `linux.uhid.usb`. `linux.usbip.usb-audio` is the distinct Real USB composite HID/UAC2 path for declared audio profiles, **not** a Wii speaker alternative. `linux.uinput` carries no Wii speaker-data path. Preserve these IDs, levels and realization restrictions.

## Options

| | A — library-only journal consumer | B — PipeWire capture-style source |
| --- | --- | --- |
| Application contract | Caller explicitly opts into Wii speaker records, polls typed accepted controls/data with a cursor and renders/records samples itself | On explicit Wii speaker-source opt-in, vg owns a **mono PipeWire source node** in the caller's session; any app may explicitly record it or connect it to a playback sink |
| Controller/protocol role | Wii family decoder and journal own validation, accepted order and ADPCM state; caller owns audio device/graph, resampling and playback | **Same** authoritative decoder/journal; a bounded, nonblocking feeder converts accepted data to PipeWire PCM, not a second HID decoder or journal |
| Isolation and permissions | No new vg host surface beyond existing UHID and journal access. Caller obtains its own audio-output access if listening | Adds caller-session PipeWire socket/node access and a creation/teardown responsibility; does not add ALSA kernel hardware, UAC function, broker/worker messages or privileged grants |
| Cost and portability | Smallest surface; no vg audio-backend dependency; caller must implement playback | Reusable system-graph source for recorders and monitors, but Linux/PipeWire only and requires graph/underrun/lifecycle qualification |
| Status | **Recommended first implementation**, contingent on S1 family journal wiring | **Follow-on proposal**, not authorized or automatically available on the Native HID tier |

Option B is **not** a fake UAC device under ADR-0023: the node is an explicitly labeled *host-side rendering of decoded in-band speaker commands*, associated with an existing UHID controller but without USB descriptors, device matching or independently claimable hardware speaker capabilities. Do not attach Wii to the existing DualSense/DS4/Xbox360 UAC profile, change the realization ID or start the root broker. If a requested design turns out to require IPC or broker work, stop rather than expanding this brief.

## Shared conversion and playback policy

1. **Source/rate.** Consume only journal `Accepted` Wii speaker-data records at the approved semantic boundary, preserving order and typed control/configuration changes. The decoder recognizes Yamaha ADPCM (`0x00`, **two** signed `i16` samples per encoded byte) and signed PCM8 (`0x40`, **one** `i16` sample per byte). Source-model nominal rates are **6,000,000/divisor** for ADPCM and **12,000,000/divisor** for PCM; the current `sample_rate_hz` field truncates to an integer, with zero divisor/unknown format returning no rate. For playback scheduling, derive the *rational* nominal rate from the recorded raw divisor and format (rather than assuming the truncated display integer is an exact clock). Resample mono using a bounded stateful converter to the **actual negotiated graph/device rate** (48 kHz only when selected/negotiated), with anti-alias filtering for downsampling. On rate/format changes, end/reset the resampler segment without silently resetting the native ADPCM predictor. Neither the divisor nor journal arrival time proves an actual physical sample clock.
2. **Volume and controls.** Preserve the **raw one-byte volume register** and report it in diagnostics. Neither `0x40` nor `0x7f` is a proven physical maximum; never normalize, clamp, reject or apply an inferred retail gain curve. A prototype may use unity software gain with an *independent, user-controlled* monitor gain, explicitly labeled nonphysical. Honor valid mute and enable transitions in the **rendered** output: muted reports supply no decoded samples under the current source model; disabled-but-decoded samples remain journal data but are suppressed by the renderer by default. Do not erase control records, replay buffered sound on unmute/re-enable or conflate host enable with Dolphin's separate application speaker preference. A zero-volume register does not prevent decoding; audible suppression at zero is a configurable application policy, not a verified hardware rule.
3. **Loss and silence.** Track `epoch/sequence`, read the ring in bounded batches, and never reconstruct playback from `service()`, `host_outputs()` or an unverified read start. A `SequenceGap` can contain control/configuration records as well as audio: report an audible discontinuity, discard stale render staging, resynchronize to the next known context or stop; **do not infer missing sample counts from missing sequence counts**. The controller's already-decoded post-gap samples can still be valid even when a caller's resampler history is reset. On a PipeWire underrun, graph-continuity silence must be counted and flagged as **synthesized**, not reported as received Wii samples. Close/terminal/epoch mismatch clears the feeder; new sessions never splice old audio.
4. **Latency and servicing.** Bound journal poll/service work, staging bytes, converter state and node buffers. Neither design may block HID responses or alter ACK, rumble, retained output or journal eviction behavior. A's path is host command → acceptance/journal → caller poll → resampler → caller device. B adds vg feeder → PipeWire buffer → consumer/monitor. Instrument command/record positions, samples in/out, queue occupancy, explicit loss, buffer underruns and node lifecycle. Report graph/render delay separately from unmeasured game-to-speaker/acoustic latency; no fixed latency or retail FIFO capacity is asserted.
5. **Lifecycle and access.** Default off, validate opt-in/realization/feature at creation before external I/O, no fallback to Generic or Real USB. B requires `audio-pipewire` and a running **caller-session** server; advertise a clearly nonhardware source and its controller association, then destroy it on close/rollback. Audio recording/monitor links require an explicit caller/session-manager action; never auto-connect speakers, grant broad sound access, install persistent rules, unbind a HID driver or use root. If sandboxed Dolphin cannot see the UHID/hidraw consumer, record that as a permission blocker, not a streaming failure. Any new host access policy needs a separate #258-style audit and owner sign-off.

## Deterministic tests (planned; **not run**)

- **Before either option:** accepted-only journaling of `0x14` enable, `0x19` mute, `0x16` configuration and bounded `0x18` data; identical repeats get new positions, rejected/disabled audio not mislabeled accepted, raw reports and rumble bits remain intact. Preserve current decoder tests for high-nibble-first ADPCM, signed PCM8, divisor zero, short/oversized data, unknown format, mute/disabled disposition, volume zero and cross-packet predictor state. Verify two readers, overflow gaps, epoch reset, terminal drain and no host ACK/service regressions.
- **A:** feed synthetic nominal 3,000 Hz and fractional 6 MHz/3,072 ADPCM plus 2,000 Hz PCM into a deterministic resampler at 48 kHz and at a non-48-kHz negotiated rate; check sample count/timebase tolerance, channel count, anti-alias behavior, configuration changes, muted/disabled gating, repeated values, artificial stall and non-blocking backpressure. Label no-audio periods separately from lost input.
- **B (only if later approved):** fake PipeWire/server negotiation, mono format, opt-in rejection/rollback, multiple independent controllers, caller-session access refusal, source publication/removal, monitor versus recording, bounded graph underrun accounting and no implicit UAC/ALSA device. Test source-path latency instrumentation without asserting a timing budget before measurements.

## Kalux Dolphin check (planned; **not run**)

On a documented kalux build with opt-in Wii `linux.uhid.bluetooth`, launch **Dolphin Real Wii Remote** using the virtual HID path and explicitly set Dolphin's speaker preference. Observe the native control/configuration/`0x18` sequence through the *accepted* journal and verify decoded counts, raw register context, no unreported gaps, mute/enable changes and connection/ACK behavior. Compare preference on/off and start/stop/recreate; repeat with an intentionally slow reader to prove gap detection. For A, have a separate caller play/record that stream; for B, **only after its implementation**, show the labeled PipeWire source and manually link/record/monitor it. Capture the exact candidate revision, host/consumer versions, permissions, source-side journal/sample counts, synthesized silence and any subjective audible result **as distinct observations**. A missing speaker stream is a failure/blocker, not an inferred pass. Such a run would establish at most this **virtual host/consumer** path; it would not demonstrate actual Wii hardware, radio pairing, physical transducer equivalence or acoustic latency.

## Recommended implementation order (future PRs only)

1. Finish and validate V2a/S1 Wii family journal wiring and explicit speaker opt-in on the correct Native HID Bluetooth-bus target; re-check decoder and register semantics against adopted research before promoting any accepted-data record.
2. Implement **A** as a minimal consumer example/library recipe using typed cursor replay, rational-rate resampling, conservative mute/enable handling, independent gain and explicit loss/terminal diagnostics. No vg sound device required. Validate synthetic fixtures and host service isolation.
3. Run the planned Dolphin + caller test on kalux with explicit permissions, record successes and failures, and decide whether A meets the audible-monitoring use case.
4. **Only if needed and separately approved**, add B's optional caller-session PipeWire source using the *same* journal and explicit component lifecycle; update #258 host-access review, host tests and docs. No broker, worker IPC or UAC emulation.
5. For any future public API additions, regenerate the alpha snapshot with `python3 scripts/check-alpha-api.py --write`, update `docs/ALPHA_API_MIGRATION.md`, identify every API delta in that PR, and rebase the design against current `main` by merging (never rewriting history). **This brief changes no API.**
